# Raumdeuter v2 — Agent Guide

Comprehensive engineering brief for any AI agent (Cursor, Claude, Copilot, etc.)
working on this monorepo.

> Read this whole file before touching code. The architecture, naming, and
> conventions below are non-obvious in places and the codebase will fight you
> if you ignore them.

---

## 1. Project at a glance

A football scouting / analytics web app. Migration target of the legacy
Streamlit app at `~/Projects/raumdeuterapp/`. Same data, new stack.

- **Domain**: per-player Wyscout stats across 36 leagues, 12 seasons (2015–2026).
- **Goals**: fast (DuckDB on parquet), customizable UI (Tailwind 4 + glassmorphism
  dark theme), interactive charts (Plotly + custom SVG).
- **Non-goals (for now)**: auth, multi-tenant, mobile-first, Match Analysis.

### Stack

| Layer | Tech |
|---|---|
| Frontend | Next.js 16 (App Router, RSC + Client), TypeScript 5, Tailwind 4 (`@theme`), shadcn-style components (hand-rolled with Radix primitives), Tanstack Query 5, Zustand, Plotly + react-plotly.js, custom SVG |
| Backend | FastAPI (Python 3.12), Pydantic v2, DuckDB (in-memory views over parquets), pandas/numpy/scipy/sklearn for analytics |
| Shared | OpenAPI → TypeScript types via `openapi-typescript` (`packages/shared-types`) |
| Tooling | pnpm workspaces, `uv` (Python), Docker Compose, ruff, mypy, pytest, `next/turbopack` |
| Hosting | Vercel (web), Fly.io / Railway (api) — TBD |

## 3. Backend (FastAPI + DuckDB)

### 3.1 DuckDB conn + view registration

`app/core/duckdb_pool.py` is the single source for the connection. Module-level
singleton, `threading.Lock`, lazy init. On first call:

1. Create `:memory:` connection.
2. Register one VIEW per season parquet:
   - `players_2025`, `players_2024`, … from `data/players/all/*_all_leagues.parquet`
   - `players_all` = `union_by_name=true` of all season parquets.
3. Register team views from `data/teams/*.parquet`.
4. Register `team_profiles` from `data/teams/profiles/team_profiles.parquet`
   (used for translation strength adjustment).

**Always** use `get_conn()` to obtain the connection. **Never** open a new
DuckDB connection in routes or core modules.

### 3.2 Module boundaries

```
core/                         No FastAPI, no HTTP.
├── config.py                 Constants (LEAGUES, ROLE_TO_TOKENS, GAME_AREAS, ...)
├── duckdb_pool.py            Conn + views + fetch_all_dicts helper
├── filters.py                PlayerFilters Pydantic + build_where SQL builder +
│                             not_goalkeeper_sql / goalkeeper_only_sql
├── league_list.py            Distinct leagues per view
├── metrics_catalog.py        Allow-list of selectable metric column names
├── metric_modes.py           per90 / raw / as_is mode helpers
├── metric_sql.py             metric_sql_expr — produces safe DuckDB expression
│                             for a (metric, mode) pair
├── player_traits.py          Trait derivation from per-90 stats
├── team_strength.py          xG context × dominance × league band → strength_adj
├── text_search.py            Accent-fold word match
└── top_players.py            Top-PI leaderboard (optionally filtered)

routers/                      HTTP layer. One file per resource.
├── meta.py                   /meta/* (catalog endpoints + top-performance)
├── players.py                /players/search, /players/{id}
├── profile.py                /players/{id}/profile (radar + game areas + traits)
├── progression.py            /players/{id}/progression (multi-season time series)
├── replacement.py            /replacement (vector similarity)
├── scatter.py                /scatter
├── screener.py               /screener
├── rankings.py               /rankings
├── bar.py                    /bar (multi-player multi-metric stack)
└── translation.py            /translation (PI projection between leagues)

schemas.py                    All request / response Pydantic models.
                              Single file by design — keeps OpenAPI titles stable.
```

**Adding a new endpoint? Always:**

1. Define request + response schemas in `schemas.py`.
2. Domain logic goes in `core/` (importable, testable in isolation).
3. Router file ≤ 200 lines: parse → validate → call core → wrap response.
4. Whitelist any user-supplied column name via `selectable_metric_names()`
   before interpolating into SQL.
5. Add a smoke test in `apps/api/tests/test_endpoints.py` (TestClient).
6. Regen OpenAPI + TS types (see §5.4).

### 3.3 SQL safety

DuckDB is NOT a sandbox. Treat user input as hostile:

- Use **parametrised queries** for values (`?` placeholders).
- Column names cannot be parametrised. Whitelist them via:
  ```python
  from app.core.metrics_catalog import selectable_metric_names
  allowed = set(selectable_metric_names(conn, view))
  if user_metric not in allowed:
      raise HTTPException(400, "...")
  ```
- For column quoting, use the `_q()` helper in `routers/scatter.py` — rejects
  any name containing `"` `;` `--`.
- Season-scoped view names follow the pattern `players_{int}`. Validate via
  `if view not in list_views(): raise 404`.

### 3.4 Performance index (PI) and percentiles

- `performance_index` is a precomputed column in the parquets. Don't recompute
  it.
- Percentiles in `routers/profile.py` are computed on-the-fly via SQL
  `SUM(CASE WHEN m <= ? THEN 1 ELSE 0 END) / COUNT(*)` against the league cohort
  with `Minutes played >= min_minutes`.

### 3.5 Settings

Single `Settings` class in `settings.py` (`pydantic-settings`). Env vars use the
`RAUMDEUTER_` prefix. Default `data_dir` is auto-detected for monorepo vs
Docker via `Path` parents — don't hardcode.

```bash
RAUMDEUTER_DATA_DIR=/data
RAUMDEUTER_CORS_ORIGINS='["http://localhost:3000"]'
```

## 4. Frontend (Next.js + Tailwind 4)

### 4.1 Next.js 16 quirks (read first!)

This is **Next 16** with Turbopack. APIs differ from your training data:

- **`use client`** required at the top of any file with hooks, browser APIs, or
  Tanstack Query.
- **Server Components by default.** Pages that don't need interactivity should
  stay server-rendered. Lift `"use client"` to the smallest leaf possible.
- **Searchparams wrapping**: any client component that calls `useSearchParams()`
  must be wrapped in `<Suspense>`. See `app/scout/profile/page.tsx` for the
  pattern (server `<Suspense>` → `<*-Client>`).
- **`next/dynamic` + Plotly**: Plotly is heavy and breaks SSR. Always:
  ```tsx
  const Plot = dynamic(() => import("react-plotly.js"), { ssr: false });
  ```

### 4.2 Tailwind 4 (no config-based theme)

Tokens live in `src/app/globals.css` inside `@theme {}`, not in
`tailwind.config.ts`. To add a new colour or radius, edit `globals.css`.

```css
@theme {
  --color-primary: #14d1ff;
  --color-primary-fg: #003543;
  ...
}
```

Custom utilities use `@utility`:

```css
@utility glass {
  background: color-mix(in srgb, var(--color-surface-mid) 60%, transparent);
  backdrop-filter: blur(20px);
  border: 1px solid color-mix(in srgb, white 10%, transparent);
}
```

Usage in JSX: `className="glass rounded-lg p-6"` — no JIT errors, no `bg-glass-*`
prefix nonsense.

### 4.3 Component conventions

- `components/ui/` — primitives. No domain knowledge. Built on Radix
  (`@radix-ui/react-popover`, `react-slot`, `react-tabs`, `react-slider`,
  `react-tooltip`, `react-label`, `react-dialog`).
- `components/charts/` — visualization wrappers (Plotly + SVG).
- `components/domain/` — football-specific. Imports from `ui/` and `charts/`
  is fine; the reverse is not.
- `components/shell/` — layout chrome.

### 4.4 Data fetching

- One client: `lib/api.ts` (`openapi-fetch` + `shared-types`).
- One Tanstack Query provider: `lib/query-provider.tsx` (5min `staleTime`,
  `refetchOnWindowFocus: false`, retry 1).
- Query key conventions:
  ```ts
  ["seasons"]
  ["leagues", season]
  ["metrics", season]
  ["scatter", season, leagues, roles, age, minutes, x, y, xMode, yMode]
  ```
  Order: resource name first, then dependencies in the order they affect the
  result. Stable keys = stable cache.
- Always destructure `{ data, error }` from openapi-fetch and throw on `error`
  inside `queryFn`. React Query will surface the error via `isError`.
- Use `enabled:` to gate queries on dependencies (e.g. `enabled: !!playerId`).
- Use `useGlobalFilters` (Zustand) for cross-page filter state. Per-page
  state stays in `useState`.

### 4.5 Charts

- **Plotly** for scatter, bar, distribution, line. Theme:
  - `paper_bgcolor: "transparent"`, `plot_bgcolor: "transparent"`
  - `font: { family: "Inter", color: "#d2e2f2", size: 12 }`
  - Gridlines `rgba(255,255,255,0.05)`
  - Hoverlabel `bgcolor: "#16202e"`, `bordercolor: "#374557"`
  - Disable mode bar: `config={{ displayModeBar: false, displaylogo: false }}`
- **Custom SVG** for radar, position pitch, fingerprint. Put pure-SVG components
  in `components/charts/`. They must be `"use client"` only if they use refs or
  interaction; otherwise leave them server-renderable.

### 4.6 Profile detail panels (Compare / Progression / Replacement / Translation)

These are *self-contained* expandable panels. Pattern:

```tsx
const [open, setOpen] = React.useState(false);
const queryEnabled = open && /* ...other guards */;
const q = useQuery({ ..., enabled: queryEnabled });
```

- Don't pre-fetch panel data. Wait for the user to expand.
- Don't unmount/remount: just toggle `open` and let the query cache sit.
- Heading uses a `<button>` with `ChevronDown`/`Up`. Whole header is the toggle.

### 4.7 Routing

- `app/scout/profile/page.tsx` → server entry, wraps `<ProfileIndexClient />`
  in `<Suspense>`.
- `app/scout/profile/[wyscoutId]/page.tsx` → server entry, wraps
  `<ProfileDetailClient />`.
- All client logic lives in sibling `*-client.tsx` files. Pages are tiny.
- URL holds `?season=YYYY` — single source of truth. The page resolves season
  with this priority: URL → global store → most recent.

### 4.8 Theming reference

Source of truth: `Downloads/stitch_premium_player_analytics_hub/elite_pitch_intelligence/DESIGN.md`.

Currently in v2 (after the user requested swap to blue):
- Primary: `#14d1ff` (electric tech blue) — KPIs, active states, positive trends
- Secondary: `#00ff41` (electric green) — accents, progression deltas
- Surface: `#0a1018` (deep blue-black) → `#2a3445` (highest)
- On-surface: `#d2e2f2` / `#b2c4d8`
- Outline: `#7e8fa5` / `#374557`
- Heat scale (red→amber→green) lives in `lib/percentile-heat.ts`

## 5. Cross-cutting concerns

### 5.1 Performance

| Concern | Pattern |
|---|---|
| Cold parquet read | DuckDB views are lazy. First query reads, subsequent queries hit cache. Don't pre-load everything. |
| Memory pressure | Never `SELECT *` from a season view in Python. Project columns explicitly. |
| API payload size | Cap LIMITs (50 for rankings, 100 for screener, 30 for cards, 12 for bar). Use server-side filtering, not client-side. |
| Chart rendering | Use `scattergl` (WebGL) for >500 points. Switch to `scatter` only when text labels are needed. |
| Re-renders | Wrap derived data in `useMemo`. Pass primitive deps in query keys (not object refs). |
| Bundle size | Plotly is ~3MB. Always `next/dynamic({ ssr: false })`. Don't import from `plotly.js-dist-min` directly in shared code. |
| Hot path | `/scatter` returns 500–800 rows × 9 fields. Keep the response under 100KB by filtering NaN/null x or y server-side. |
| TanStack Query | `staleTime: 5min`, `refetchOnWindowFocus: false`. Use `placeholderData: keepPreviousData` for filter-driven queries to avoid loading flicker. |

### 5.2 Security

- **CORS** — `RAUMDEUTER_CORS_ORIGINS` is the only allowed origin list. Never
  use `["*"]` in production.
- **No auth yet** — when adding, prefer Auth.js (NextAuth) on web side, JWT
  bearer to API. Don't roll your own.
- **SQL injection** — see §3.3. Whitelist column names, parametrise values.
- **PII** — none stored (player names + clubs are public). If we add saved
  views or user accounts: scoped by `user_id` FK, never accept user-supplied
  user_id from request body.
- **Logos / images** — `wyscoutClubLogoSrc()` in `lib/wyscout-image.ts` enforces
  the allowed CDN host. Don't `<img src={user_input}>` blindly.
- **Error messages** — never leak SQL or stack traces to clients. FastAPI's
  default 500 page is fine; for known issues use `HTTPException(400, "...")`
  with a public-safe message.
- **Env vars** — never commit `.env*`. They're already in `.gitignore`. API
  keys, when added, use `RAUMDEUTER_*` prefix and load via Pydantic settings
  (so they're typed + validated at startup).

### 5.3 Testing

- **Backend**: `apps/api/tests/test_endpoints.py` — TestClient smoke tests over
  real data. Each new endpoint gets at least one. Pattern:
  ```python
  def test_my_endpoint() -> None:
      with TestClient(app) as c:
          seasons = c.get("/meta/seasons").json()
          if not seasons:
              return  # CI without data → skip
          r = c.post("/my-endpoint", json={...})
          assert r.status_code == 200, r.text
  ```
- **Frontend**: Playwright E2E (planned in `apps/web/tests/e2e/`). Visual diff
  against Stitch mockups manually for now.
- **Type safety**: `pnpm exec tsc --noEmit` must be clean before merging.
- **Lint**: ruff for Python, ESLint for TS.

### 5.4 OpenAPI → TypeScript types

Generated, not handwritten. Workflow when changing a Pydantic model:

```bash
# from monorepo root
cd apps/api
PATH="$HOME/.local/bin:$PATH" uv run python -c "import json; from app.main import app; print(json.dumps(app.openapi()))" > ../../packages/shared-types/openapi.json
cd ../..
pnpm --filter shared-types gen
```

Result: `packages/shared-types/src/api.d.ts` is updated.

If you forget this step, the web build will compile against stale types and
silently miss runtime fields.

### 5.5 Symlinked data

`data/` is a symlink to the legacy repo's `data/`. Never write to it from v2.
If you need to mutate parquets, do it from the legacy repo. v2 reads only.

## 6. How to do common things

### 6.1 Add a new metric-aware endpoint

1. Schema (`schemas.py`): Request with `PlayerFilters` + new fields. Response
   with `metric: str`, `label: str`, value rows, optional `n: int` count.
2. Router file in `routers/`. Validate metrics via `selectable_metric_names`.
   Build SQL with `metric_sql_expr(name, mode)`. Use `build_where(filters)`.
   Use `fetch_all_dicts(conn, sql, params)`.
3. Wire into `app/main.py` (`app.include_router(...)`).
4. Smoke test in `tests/test_endpoints.py`.
5. Regen TS types (§5.4).
6. Frontend: Tanstack Query hook + page or panel.

### 6.2 Add a new global filter

1. `core/filters.py`: add field to `PlayerFilters`. Update `build_where`.
2. `lib/store.ts`: extend `GlobalFilters` Zustand state.
3. `components/domain/filter-panel.tsx`: add UI control.
4. Update query keys on every page that uses the filter (otherwise stale cache).

### 6.3 Add a new sub-page under /scout

1. `app/scout/<slug>/page.tsx` — server entry, `<Suspense>` wrapper.
2. `app/scout/<slug>/<slug>-client.tsx` — `"use client"`, the actual UI.
3. Add to `SUB_NAV` in `app/scout/layout.tsx`.
4. Use `FilterPanel` + `useScoutFiltersSidebar()` for left sidebar UX
   (collapse / expand pattern).

### 6.4 Add a new chart component

1. File in `components/charts/<name>.tsx`. `"use client"` if interactive.
2. Take primitive props (arrays, scalars, label strings) — no domain types.
3. Plotly: wrap with `dynamic(() => import("react-plotly.js"), { ssr: false })`.
4. Memoize the `data` array with `useMemo` keyed on raw inputs.
5. Theme: see §4.5.

### 6.5 Boot dev environment

```bash
# API
cd apps/api
PATH="$HOME/.local/bin:$PATH" uv run uvicorn app.main:app --reload --port 8000

# Web (separate terminal)
cd apps/web
pnpm dev    # http://localhost:3000

# Or both via Docker:
docker compose up --build
```

### 6.6 Run tests

```bash
# API
cd apps/api
PATH="$HOME/.local/bin:$PATH" uv run pytest -q

# Web typecheck
cd apps/web
pnpm exec tsc --noEmit
```

## 7. Anti-patterns (do not do)

- ❌ Importing from `streamlit` anywhere in v2. The legacy app uses it; v2 doesn't.
- ❌ Recomputing `performance_index` client-side or in a router. It's a column.
- ❌ Adding domain logic to `routers/`. Push it down to `core/`.
- ❌ Hardcoding `data_dir` paths. Use `settings.data_dir`.
- ❌ Building SQL with f-string interpolation of user values. Always `?` params.
- ❌ Spawning a new DuckDB connection per request. Use `get_conn()`.
- ❌ Using `getServerSession`-style imports in Next 16. Different APIs now.
- ❌ Putting `"use client"` at the top of every file. RSC-first.
- ❌ Importing `react-plotly.js` directly without `next/dynamic`.
- ❌ Editing `tailwind.config.ts` to add colours. Use `globals.css` `@theme`.
- ❌ Bypassing `selectable_metric_names()` allow-list. SQL injection vector.
- ❌ Committing `.env` files or secrets. They're gitignored — keep it that way.
- ❌ Renaming Wyscout columns. They have spaces, accents, percent signs.
   Use double quotes when interpolating column names; the legacy schema is the
   source of truth.

## 9. Senior Engineer Checklist

Before opening a PR / committing, run through:

- [ ] Schema change → OpenAPI regen → TS types regen (§5.4)
- [ ] New SQL → user inputs whitelisted (§3.3)
- [ ] New endpoint → smoke test added (§5.3)
- [ ] New page → server `<Suspense>` wrapper, client component sibling (§4.1)
- [ ] New filter → query keys updated everywhere (§6.2)
- [ ] `pnpm exec tsc --noEmit` clean
- [ ] `uv run pytest -q` green
- [ ] No new `streamlit` import, no new `getServerSession`, no `as any` smuggled
- [ ] Plotly imports wrapped in `next/dynamic`
- [ ] Performance: capped LIMITs, no `SELECT *` in hot paths, memoized derived data
- [ ] Caveman mode does NOT apply to code/commits (write code normally)
